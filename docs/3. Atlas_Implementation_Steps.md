# ATLAS-Enterprise-AI —  Step-by-Step Implementation Order


## 1 — Setup and infrastructure

1. **`requirements.txt`** — Define dependencies for FastAPI, LangGraph, boto3, Pinecone, PostgreSQL, and Rius instrumentation.
2. **`.env.example` → `.env`** — Configure AWS credentials, Bedrock models, S3 bucket, Pinecone, Render PostgreSQL, and Rius settings. Never commit `.env`.
3. **`app/config.py`** — Centralize environment-variable loading and application configuration.
4. **`infra/schema.sql`** — Define database tables for documents, chat history, HITL approvals, feedback, and audit events.
5. **`app/db.py`** — Configure PostgreSQL connections and database helpers.
6. **`scripts/init_db.py`** — Create and verify the database schema.
7. **`app/aws.py`** — Configure AWS clients, S3 operations, Bedrock Nova Lite chat, and Titan V2 embeddings.
8. **`app/vector.py`** — Implement Pinecone index creation, vector upsert, and similarity search.

## 2 — Document ingestion and RAG

9. **`worker/ingest.py`** — Download uploaded documents from S3, extract text, split into chunks, generate Bedrock embeddings, upsert vectors into Pinecone, and update document status in PostgreSQL. Explain how this function is invoked; a file in `worker/` does not run automatically.
10. **`app/rag.py`** — Implement or connect retrieval and RAG helpers. In some project versions, this module is a re-export; inspect the actual implementation before teaching it.
11. **`app/memory.py`** — Persist and retrieve conversation history from PostgreSQL.
12. **`app/guardrails.py`** — Implement deterministic input/output checks for prompt injection, sensitive requests, and unsafe responses.
13. **`app/graph.py`** — Assemble the LangGraph flow: input checks → memory/retrieval → Bedrock generation → output checks, with HITL routing for sensitive actions.

## 3 — Observability with GlassFlow Rius

14. **`app/observability.py`** — Configure optional Rius tracing, service name, API key, and privacy-safe defaults.
15. **`app/graph.py`** — Instrument LangGraph nodes to observe execution duration and errors.
16. **`app/aws.py` and `app/vector.py`** — Add traces around Bedrock calls and Pinecone operations.
17. **`worker/ingest.py`** — Trace document ingestion stages and failures.
18. **Rius dashboard** — Confirm traces arrive during test runs; never expose secrets or sensitive document contents in telemetry.

## 4 — FastAPI and user interface

19. **`app/main.py`** — Implement routes for presigned S3 upload, ingestion, documents, chat, approvals, and metrics. Connect the backend to the graph and ingestion workflow.
20. **`app/templates/index.html`** — Build the chat, document-upload, documents, approvals, and metrics views using the project's existing HTML/JS stack.
21. **`app/static/css/styles.css`** — Style the interface and constrain chat history to a fixed-height, vertically scrollable panel.
22. **`app/static/js/app.js`** — Wire API calls, presigned uploads, approval buttons, chat rendering, and auto-scroll to the latest message.

## 5 — Integration and validation

23. **Amazon S3 CORS** — Allow browser PUT uploads from the exact local origins, e.g. `http://127.0.0.1:8000` and `http://localhost:8000`.
24. **`tests/`** — Verify upload/ingestion, retrieval and citations, conversation memory, guardrails, HITL approval records, Rius traces, and scrollable chat behavior.
25. **`docs/SETUP.md` and `docs/RIUS_OBSERVABILITY.md`** — Document credentials, setup, privacy settings, testing, and troubleshooting.
26. **End-to-end demonstration** — Initialize the database, start FastAPI, upload a sample document, ask grounded questions, test memory/guardrails/HITL, and inspect traces in Rius.
